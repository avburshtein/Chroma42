# Chroma42 — методология проверки доступности цвета

*Публичное описание для внешнего читателя: клиента, аудитора, коллеги без доступа к коду.*
*Нормативная база: `Docs/Chroma42 Color Pair Methodology.md`, версия 2.0.0.*

---

## Что делает Chroma42

Chroma42 генерирует цветовые токены и проверяет их **измеримым методом**:
не «цвет выглядит доступным», а конкретная пара текст/фон проходит конкретный
порог контраста конкретного стандарта. Результат — паспорт со списком
проверок, а не общее заявление о доступности.

Chroma42 покрывает **цветовую часть** доступности интерфейса. Семантика
HTML, клавиатурная навигация, ARIA-атрибуты, размер целей и поведение
компонентов — вне области действия инструмента.

---

## 1. На какие стандарты опирается проверка

| Стандарт | Что именно используется |
|---|---|
| **WCAG 2.2** (W3C Recommendation, 12.12.2024) | Критерии 1.4.3, 1.4.6, 1.4.11, 2.4.13 — единственные критерии WCAG, относящиеся к цвету |
| **EN 301 549 v3.2.1** (ETSI, 2021) | Европейский стандарт доступности; в части визуального контраста опирается на WCAG — Chroma42 покрывает эту часть через реализацию WCAG |
| **ГОСТ Р 52872-2019** | Рекомендательный документ; собственных числовых порогов контраста не содержит и отсылает к WCAG — Chroma42 покрывает применимую часть через реализацию WCAG |
| **APCA** (спецификация 0.1.9) | Независимая модель контраста, не входящая в WCAG. Используется только как дополнительный аналитический показатель, не как критерий прохождения |

Критерии WCAG 2.2, которые применяются к цвету:

| Критерий | Название | Уровень | Порог |
|---|---|---|---|
| 1.4.3 | Contrast (Minimum) | AA | 4.5:1 обычный текст, 3:1 крупный |
| 1.4.6 | Contrast (Enhanced) | AAA | 7:1 обычный текст, 4.5:1 крупный |
| 1.4.11 | Non-text Contrast | AA | 3:1 для значимых графических элементов и границ |
| 2.4.13 | Focus Appearance | AAA | 3:1 между сфокусированным и несфокусированным состояниями |

Часть порогов в строгих профилях Chroma42 (например, 4.5:1 для индикатора
фокуса) строже, чем требует сам стандарт — это отмечено как собственная
политика проекта, а не норма WCAG.

---

## 2. Как считается контраст

Контраст между двумя цветами вычисляется по формуле относительной яркости
из WCAG: каждый цвет переводится в линейное пространство sRGB, из каналов
R/G/B с весами вычисляется яркость, а коэффициент контраста — это
отношение яркостей более светлого и более тёмного цвета (по шкале от 1
до 21). Формула симметрична: порядок цветов в паре не влияет на результат.

Прозрачные токены не проверяются «как есть» — WCAG не умеет работать
с альфа-каналом. Токен сначала математически «запекается» на заявленной
подложке (обычной альфа-композитинг), и только получившийся непрозрачный
цвет проверяется по стандартной формуле. Если подложка не указана явно,
токен получает статус «требует ручной проверки», а не считается
автоматически доступным.

Сами тональные шкалы строятся в пространстве **OKLCH**, а не HSL — оно
перцептивно равномерно, то есть одинаковое числовое значение светлоты
у разных оттенков воспринимается человеком одинаково светлым. Это не
влияет на формулу контраста (она всегда работает в sRGB), но даёт
предсказуемые, визуально ровные тональные ряды без ручной подгонки.

---

## 3. Что именно проверяется — пары, а не цвета

Отдельный цвет не бывает «доступным» или «недоступным» — доступной или
недоступной бывает конкретная **пара** в конкретном контексте использования
(текст на поверхности, значок на кнопке, граница поля, кольцо фокуса).
Поэтому Chroma42 ведёт реестр пар и проверяет каждую по своему порогу.

| Категория | Что проверяется |
|---|---|
| Текст | Основной и вторичный текст на поверхностях и в контейнерах |
| Акценты и контейнеры | Текст/иконки на primary, secondary, tertiary и их контейнерах |
| Статусы | Success, warning, error, info — цвет и его контейнер |
| Формы и фокус | Границы полей, активные границы, индикаторы фокуса |
| Стеклянные поверхности | Прозрачные токены, проверенные против конкретной подложки |

На текущей версии реестра: **30 пар, из них 24 обязательные** для
прохождения экспорта в строгих профилях.

---

## 4. Профили строгости

Проверка выполняется не по одному фиксированному порогу, а по выбранному
профилю:

| Профиль | Уровень | Строгость |
|---|---|---|
| `standard-aa` | WCAG 2.2 AA | базовый |
| `standard-aaa` | WCAG 2.2 AAA | повышенный |
| `gov-aa` | AA + ссылка на ГОСТ Р 52872-2019 | строгий |
| `gov-aaa` | AAA + ссылочные стандарты | строгий |
| `gov-high-contrast` | текст 7:1, фокус 4.5:1 | строгий |
| `reduced-transparency` | AA + запрет прозрачности | строгий |

В строгих профилях экспорт темы **блокируется**, если хотя бы одна
обязательная пара не проходит порог — тема не может «незаметно» уйти
в продакшн с проваленной проверкой.

---

## 5. Насколько можно доверять результату — уровни уверенности

Chroma42 явно помечает, насколько крепко проверена каждая пара, вместо
того чтобы одинаково маркировать всё как «проверено»:

| Уровень | Что значит |
|---|---|
| `verified` | Сплошные цвета, контраст рассчитан напрямую и проходит порог |
| `verified-with-backdrop` | Прозрачный токен проверен через композитинг с явно указанной подложкой |
| `conditional` | Пара проходит только при соблюдении заявленных условий |
| `requires-manual-review` | Инструмент не может гарантировать результат (например, текст поверх фото или градиента с неизвестной подложкой) — это никогда не выдаётся за «пройдено» |

## 6. Пример паспорта темы

Каждая сгенерированная тема сопровождается паспортом — машиночитаемым
отчётом о том, что именно было проверено:

```json
{
  "passportVersion": "1.0",
  "engineVersion": "chroma42-oklch-solver-1.0.0",
  "generatedAt": "2026-09-28T12:00:00Z",
  "methodology": {
    "name": "Chroma42 Color Pair Methodology",
    "version": "2.0.0",
    "policy": "gov-aa",
    "colorSpace": "OKLCH"
  },
  "summary": {
    "totalPairsChecked": 180,
    "passed": 178,
    "warnings": 2,
    "failed": 0,
    "exportAllowed": true
  },
  "checks": [
    {
      "pair": "on-primary/primary",
      "mode": "light-normal",
      "requiredRatio": 4.5,
      "actualRatio": 5.6,
      "status": "pass",
      "importance": "required",
      "confidence": "verified"
    }
  ]
}
```

`totalPairsChecked` — это фактическое число проверок (пары × режимы),
а не декларативная цифра из документации. Для полного набора это 30 пар
× 6 режимов = 180 проверок.

## 7. Что Chroma42 намеренно не делает

Честный список ограничений — чтобы паспорт не читался как гарантия
большего, чем есть на самом деле:

1. Проверяется только цвет. Семантика HTML, клавиатурная навигация,
   ARIA, размер целей — вне зоны ответственности.
2. Проверяется одна заявленная подложка за раз; токен поверх
   произвольного контента (фото, видео) требует ручного аудита.
3. Эффект размытия (blur) не имеет нормативного порога ни в одном
   стандарте — получает непрозрачный фолбэк, но не «проходит проверку».
4. Симуляции цветовой слепоты — эвристика, не нормативный критерий;
   результат — повод добавить нецветовой признак, а не основание
   для блокировки экспорта.
5. APCA — только аналитический показатель, не критерий прохождения.
6. Реестр пар покрывает базовые роли интерфейса; специфичные для
   продукта пары (например, текст поверх графика) добавляются вручную.
7. Полный аудит требует рендера: формулы работают со значениями
   токенов, а не со скриншотами — субпиксельное сглаживание и
   реальные шрифты не учитываются.

---

## 8. Юридический дисклеймер

> Chroma42 обеспечивает математическую валидацию цветовых контрастов и
> генерацию фолбэков в соответствии с методологиями WCAG 2.2 и ссылочными
> требованиями EN 301 549 v3.2.1 / ГОСТ Р 52872-2019. Итоговое соответствие
> цифрового продукта стандартам доступности зависит также от семантики
> HTML, клавиатурной навигации, ARIA-атрибутов, размера целей и поведения
> компонентов, что находится вне зоны ответственности генератора токенов.
> Данный отчёт не является юридическим сертификатом доступности.
